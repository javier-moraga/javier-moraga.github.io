Case study

SAS → BigQuery migration

The problem. Migrate legacy analytical processes without losing their business meaning.

My role. I co-led the migration with a colleague: process analysis, data integrity checks, reconciliation and parallel reporting. Business users validate migrated outputs before a SAS process is retired.

Approach. Map sources, targets and actual dependencies.

  • SAS
  • Python
  • BigQuery SQL

Context

Business rules were embedded in legacy processes and their dependencies. Preparation had to account for filters, joins, macros, dates and aggregation grain before assessing candidate SQL.

Approach

  1. Map sources, targets and actual dependencies.
  2. Record execution order, mappings and risks in a structural contract.
  3. Prepare candidate SQL and review schema and semantic behavior.
  4. Run SAS and BigQuery outputs in parallel over equivalent populations and periods; investigate every difference.
  5. Retire a SAS process only after business users validate its migrated outputs.

What this work produced

Each migrated process gets a structural contract, a BigQuery translation, reconciliation records and parallel reporting. Business users validate the migrated outputs before the corresponding SAS process is retired.

Technical detail

Python tooling extracts and organizes legacy structure. SAS and BigQuery SQL require semantic review as well as compatible schemas. Business users decide formal acceptance; data engineering provides ingestion and platform dependencies.

Engineering considerations

Discovering dependencies adds preparation work. Comparing equivalent outputs before redesign helps distinguish translation differences from intended business-rule changes. Parallel reporting keeps consumers on a validated source until the migrated output is accepted.

Illustrative example using synthetic data

Illustrative example using synthetic data. This describes a numeric filtering rule, not production code or a universal missing-value policy.

Consider an ordinary SAS numeric missing value (.) and a non-missing numeric cutoff. In the illustrated SAS comparison, reading < cutoff retains the missing value. If retaining missing values is intended, handle NULL explicitly and compare missing and non-missing populations separately.
