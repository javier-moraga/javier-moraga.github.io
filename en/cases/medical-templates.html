Case study

Medical Templates Framework

The problem. Keep analytical field identity consistent while form definitions change.

My role. I defined metadata rules, SQL-generation boundaries and acceptance criteria, and reviewed the framework’s evolution. Implementation and operation were shared across teams.

Approach. Capture a definitions snapshot, separately from operational records.

  • Python
  • BigQuery SQL
  • Metadata

Context

Changing form labels, types and versions require stable definitions for downstream analysis. A readable name alone does not establish that two fields mean the same thing.

Approach

  1. Capture a definitions snapshot, separately from operational records.
  2. Resolve identity using usage, validity and definition date; surface ambiguity for human review.
  3. Generate SQL for inspection rather than executing warehouse changes locally.
  4. Review the generated changes and check results after external execution.

What this work produced

The framework provides reusable analytical structures and explicit review points. Information was used by medical teams at the documented review; a consolidated layer for form usage and completeness was still in development.

Technical detail

Python / Flask supports the local maintainer; BigQuery SQL expresses catalogs, transformations and views. Upstream ingestion belongs to data engineering. SQL execution is external to the maintainer, while domain users contribute field meaning.

Engineering considerations

Separating SQL generation from execution makes changes reviewable and requires a handoff. Naming rules reduce hidden assumptions but leave ambiguous identity for human resolution. Generator tests, SQL parsing and join-multiplication checks cover specific failure modes rather than every view.
