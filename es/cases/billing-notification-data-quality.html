Caso detallado

Calidad de datos en notificaciones

El problema. Una cuenta facturable no implica necesariamente una notificación esperada.

Mi rol. Usé SQL para comparar poblaciones de cuentas entre ciclos de facturación e investigar diferencias en la elegibilidad de notificación.

Método. Comparar poblaciones de cuentas entre ciclos de facturación.

  • SQL
  • Ciclos de facturación
  • Calidad de datos

Contexto

Cuentas y clientes son unidades de análisis distintas: un cliente puede tener varias cuentas. Comparar notificaciones requiere una población elegible explícita para cada ciclo.

Método

  1. Comparar poblaciones de cuentas entre ciclos de facturación.
  2. Investigar diferencias y brechas de notificación.
  3. Usar el ejemplo siguiente para distinguir eventos esperados de observados antes de interpretar la cobertura.

Qué produjo este trabajo

Mi aporte fue la comparación y la identificación de brechas para revisión. El ejemplo explica el enfoque de conciliación; no reproduce resultados de producción.

Detalle técnico

En el ejemplo, cada fila representa una cuenta y un ciclo. Solo las filas con una notificación esperada forman parte del denominador. Los identificadores de cuenta no entregan un conteo de clientes.

Consideraciones de ingeniería

Antes de aplicar este patrón, acordar la elegibilidad y los cortes de ciclo con el responsable del proceso. Revisar claves duplicadas, registros sin correspondencia y poblaciones elegibles vacías. La cobertura no está definida cuando no se espera ninguna notificación.
